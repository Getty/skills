# Implementation plan

## Contract

User-visible behavior; canonical data model; valid states/transitions; authorization/trust boundaries; resource owners; cancellation/conflict behavior; size and concurrency limits.

## Changes

List narrowly scoped files/modules, dependency changes justified by the decision record, schema migrations, and integration boundaries. Preserve the existing project conventions.

## Acceptance

Happy path, empty/loading, malformed input, denied operation, timeout/cancellation, stale completion, persistence/reload, accessibility, resource cleanup, production artifact behavior, and rollback.

## Evidence and handoff

Exact commands to execute, target environments, results, unexecuted checks, operational ownership, and residual risk. Do not pre-fill a PASS before execution.
