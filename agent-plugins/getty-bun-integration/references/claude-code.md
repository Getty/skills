## Select the adapter

Confirm the target Claude Code version and surface support native mods. A mod uses `.claude-plugin/plugin.json`, `hooks/hooks.json`, and a module exporting `register(on, options)`. The module path is relative to `hooks/hooks.json`. Prefer declarations generated by the installed client when they differ from published types. [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)

Use a native mod for the small setup-guidance adapter where supported. Keep the application's TypeScript execution separate. If the target lacks mods, provide an explicitly invocable setup skill; optionally add a command-based context hint using an interpreter already available on that target. Do not make this hint require the missing Bun runtime.

## Inject conditional setup guidance

Package a real `skills/setup/SKILL.md` with the consumer. It must describe the setup and verification procedure from [contract.md](contract.md), including the canonical `package.json` declaration. The following example only points the agent to that file.

In `hooks/hooks.json`:

```json
{
  "modules": ["./register.js"]
}
```

In `hooks/register.js`:

```javascript
/** @type {import("claude-code").Register} */
export const register = (on) => {
  on("prompt.context", async ($, event, next) => {
    const base = await next(event);
    const root = $.plugin.root;
    const name = `${$.plugin.name}:getty-bun-setup`;
    return {
      ...base,
      blocks: [
        ...base.blocks.filter((block) => block.name !== name),
        {
          name,
          text:
            `Before executing this plugin's Bun code, verify the runtime ` +
            `declared in ${root}/package.json and its dependencies. ` +
            `If setup or repair is needed, read ${root}/skills/setup/SKILL.md ` +
            `and follow it within the current session's authorization. ` +
            `Recheck after setup and before execution. This is guidance, ` +
            `not a report that the runtime is ready.`,
        },
      ],
    };
  });
};
```

This uses host-provided plugin metadata and middleware; it imports no runtime package. The JSDoc import is a type annotation. Its API shape was checked against `Register`, `CoreEngineInterface.plugin`, `Events['prompt.context']`, and `PromptContextResult` in the [published declarations at commit fa0dece](https://github.com/anthropics/claude-code/blob/fa0dece70669a54b3104c618de9eebaaa78af19f/mods/types/claude-code.d.ts). **It has not been tested end to end in a running Claude Code client.**

## Distinguish context from execution

`prompt.context` is computed for conversation context and cached. A custom block already sent to the model is not a live status channel; even invalidating the computation does not imply replacing that block in the existing conversation. Keep the text conditional. `$.prompt.submit` can initiate a main-agent turn; `$.model.complete` has no tools. [Published API declarations](https://github.com/anthropics/claude-code/blob/fa0dece70669a54b3104c618de9eebaaa78af19f/mods/types/claude-code.d.ts)

If an integration deliberately submits a setup turn, implement an in-flight guard and deduplication; stop automatic retries after failure, interruption, or refusal. Respect session authorization rather than imposing repeated confirmations. Prefer the simpler guidance-only adapter until actual automatic-turn behavior has been tested.

Classic settings hooks differ: `type: "prompt"` evaluates a decision; `type: "agent"` runs a verification subagent. Matching settings hooks run concurrently. Neither hook array order nor a prompt evaluator establishes a completed setup barrier. [Hooks reference](https://code.claude.com/docs/en/hooks)

## Gate the actual execution

1. Resolve the consumer's exact version and verified target using [contract.md](contract.md). Use the current execution environment's user home, not a path copied from another machine or WSL host.
2. Resolve the executable under `~/.getty/runtimes/bun/<version>/<target>/bin/bun` (`bun.exe` on Windows) to an absolute path. Do not use an arbitrary PATH Bun or mutable `current` link.
3. Recheck runtime readiness when executing. Cached prompt context, a setup-completed message, or an old state file cannot replace that check.
4. Invoke normal application runs with `--no-install`. Provision dependencies during setup; recurring hooks must not download dependencies or upgrade Bun.
5. Gate only this consumer's Bun-dependent work. Keep the agent's shell and file tools available so setup can complete. For unavailable optional hooks, return a clear setup hint using the event's supported output, without claiming successful application execution.

## Review activation and validate

Respect workspace trust and the target client's hook controls. After editing manifests or hook code, follow that client's supported reload flow and inspect which definition is active. A file write alone does not prove activation. [Claude Code hook behavior](https://code.claude.com/docs/en/hooks)

Validate the plugin with the target client and exercise: Bun absent; matching runtime present; wrong version/target; interrupted setup; two simultaneous sessions; dependency failure; and a path containing spaces. Confirm that the hint loads without external Bun, only this consumer's work waits, and every application invocation uses the selected absolute executable. Record actual client versions and results; do not promote this source-checked example to a tested adapter without those observations.
