# Core model and relation selection

## Decide what each node represents

Use `prov:Entity` for a thing described through fixed relevant aspects. It may be physical, digital, conceptual, or otherwise identifiable. A file's exact bytes, a published document revision, a particular database snapshot, and a claim record are reasonable entities when their identity contracts are explicit. An entity need not be an entire immutable physical object; its fixed aspects define the modeled view.

Use `prov:Activity` for something occurring over a period and acting on or with entities. A conversion run, measurement procedure, editorial correction, or transport operation can be an activity. Use `prov:Agent` for responsibility: people, organizations, and software can be agents. PROV-O supplies `prov:Person`, `prov:Organization`, and `prov:SoftwareAgent` specializations.

Separate the source code or software release, the responsible software agent, and a particular execution when those distinctions matter. A software artifact can have its own provenance. Its execution is still a distinct event in the history. PROV forbids an identifier from being both entity and activity; agent and entity are not universally disjoint. Do not invent blanket disjointness between all three core classes.

## Read the edge in its asserted direction

| Pattern | Plain-language meaning |
| --- | --- |
| `run prov:used input` | The activity used the entity |
| `output prov:wasGeneratedBy run` | The activity generated the entity |
| `output prov:wasDerivedFrom source` | The entity was derived from the other entity |
| `output prov:wasAttributedTo agent` | Responsibility for the entity is attributed to the agent |
| `run prov:wasAssociatedWith agent` | Responsibility for the activity is associated with the agent |
| `delegate prov:actedOnBehalfOf principal` | One agent acted on behalf of another |
| `entity prov:wasInvalidatedBy run` | The activity invalidated the entity |
| `laterRun prov:wasInformedBy earlierRun` | An entity generated by the earlier activity informed the later activity |

Prefer the specific supported relation over generic `prov:wasInfluencedBy`. However, retain generic influence if that is all the evidence establishes. Do not fabricate the mechanism merely to produce a denser graph.

A list of inputs and outputs does not prove every possible pairwise derivation. For a job producing separate reports from separate files, record the dependency actually known. If only job-level dependence is available, describe that granularity and leave finer relationships unspecified.

## Distinguish common kinds of derivation

Use `prov:wasRevisionOf` when the output revises a prior entity, `prov:wasQuotedFrom` when it repeats part or all of a source, and `prov:hadPrimarySource` when the relevant primary-source relationship is supported. These are more specific derivation relationships. “Primary” is about the source relationship in the modeled history; it is not a reliability score.

Keep content derivation distinct from general citation, similarity, and shared subject matter. A report that cites a book may have used it, but a citation alone does not justify every stronger provenance claim. A vector similarity score provides no production history. Explain which evidence establishes copying, revision, transformation, or source use.

## Minimal synthetic graph

```turtle
@prefix ex: <https://example.org/prov/> .
@prefix prov: <http://www.w3.org/ns/prov#> .

ex:raw a prov:Entity .
ex:worker a prov:SoftwareAgent .
ex:convert a prov:Activity ;
    prov:used ex:raw ;
    prov:wasAssociatedWith ex:worker .
ex:clean a prov:Entity ;
    prov:wasGeneratedBy ex:convert ;
    prov:wasDerivedFrom ex:raw .
```

This states a conversion history and one responsibility relation. It does not claim that the cleaned output is accurate, that the software was authorized, or that all dependencies were captured. Add such evidence through clearly defined application records if needed.

Consult [PROV-DM](https://www.w3.org/TR/prov-dm/) for conceptual meaning and [PROV-O](https://www.w3.org/TR/prov-o/) for RDF vocabulary. Use the [Primer](https://www.w3.org/TR/prov-primer/) for explanatory patterns.
