# SONOFF and eWeLink

SONOFF (ITEAD) is the hardware brand. eWeLink (CoolKit) is the cloud/app platform used by SONOFF and other vendors, and `eWeLink` also appears as a Zigbee manufacturer string. Choose the integration by transport and firmware, never by either name. Range snapshot from the [SONOFF store catalog](https://sonoff.tech/products.json) and the [Z2M SONOFF converter](https://github.com/Koenkk/zigbee-herdsman-converters/blob/master/src/devices/sonoff.ts), 2026-10. New SKUs appear often, so check the exact model.

## Identify the line from the label or model ID

- **SNZB-NN** = SONOFF Zigbee sensor: 01 button, 02 temp/humidity, 03 PIR, 04 contact, 05 leak, 06 presence, 09 siren. No suffix = Gen1. **P** = later generation. **PR2** = second revision of a P model. Letters after 02 are per-model (D display, LD probe, WD waterproof, B lite, M pressure, UL e-ink). On 01, `M` means four-way, so read the product name. **SNZT** = Zigbee/Thread Gen3.
- **ZB** in the name means Zigbee (ZBMINI, ZBM5, S26R2ZB, S40ZBTPB, MINI-ZB…, BASIC-ZB…). Matter Wi-Fi models end in **M** (MINIR4M, S60TPG-M), say "Matter" in the product name, or are the Gen5 `-1GS/-2GS/-DIM/-RBS` names without ZB. **R2/R3/R4** are hardware revisions, and the chip can change between them. **L/L2** = no neutral. **-E** = Fusion/Orb EU wall version. **TPF/TPG/TPB** = Type F/G/B socket.
- **Zigbee strings:** current devices report manufacturer `SONOFF`, Gen1 often `eWeLink`. Gen1 model IDs include `WB01`, `TH01`, `MS01`/`MSO1`, `DS01` and `CK-TLSR8656-SS5-01(7000/7014/7002/7003)` for SNZB-01/-02/-03/-04. White-labels share these (eWeLink RHK06–09, SQ510A, Zbeacon TH01, Woolley SA-028/029). The manufacturer code is 0x1286 (Shenzhen CoolKit).
- **Wi-Fi:** SonoffLAN's [device table](https://github.com/AlexxIT/SonoffLAN/blob/master/DEVICES.md) maps the eWeLink model and UIID ("Hardware firmware" in the app) to local-protocol support. For example, UIID 138 covers BASICR4/MINIR4/MINIR4M/MINI-D, and 190 covers POWR320D/S60TPF.

## Route rules

- Pair Zigbee devices directly to the HA coordinator. A child of an eWeLink bridge reaches HA only through cloud, SonoffLAN, a Matter bridge or Bridge-M MQTT, and each of those limits entities and offline behavior.
- [SonoffLAN](https://github.com/AlexxIT/SonoffLAN) (HACS) supports `auto`, `local` and `cloud` modes. Local mode needs the device keys, which it downloads from the cloud once, plus working mDNS multicast. Devices in DIY mode need no credentials. The author recommends `auto`. Check `DEVICES.md` for local support.
- The official [eWeLink Smart Home add-on](https://github.com/iHost-Open-Source-Project/hassio-ihost-addon/tree/master/hassio-ihost-ewelink-smart-home) syncs the eWeLink account to HA over MQTT. It replaces the archived [CoolKit add-on](https://github.com/CoolKit-Technologies/ha-addon), which SONOFF's [HA guide](https://sonoff.tech/en-us/blogs/news/how-sonoff-works-with-home-assistant) still links. It has no device UI and no HA→eWeLink sync.
- DIY mode is an unencrypted LAN HTTP API that was documented for BASICR3, RFR3 and MINI ([protocol doc](https://github.com/itead/Sonoff_Devices_DIY_Tools)). Do not assume R4 or newer models offer it.
- Reflash only an ESP-based unit after checking the template and chip. Flashing loses eWeLink and Matter certification, needs serial access to a mains device, and is hard to reverse.
- Do not let SonoffLAN, the add-on and Matter command the same device at once. Pick one controller path.

## Worked examples

**SNZB-02P (P temp/humidity).** Z2M exposes temperature, humidity, battery, calibration offsets and OTA. It uses a CR2477 cell. Check the report cadence and confirm a physical temperature/humidity change. Calibrate only after a stable comparison with a reference. An offset does not correct a sensor mounted near a radiator. [SNZB-02P](https://www.zigbee2mqtt.io/devices/SNZB-02P.html).

**SNZB-01P (P button).** Supports single, double and long actions. It sleeps, so press it to keep it awake during configuration. Z2M documents that binding the `OnOff` cluster succeeds but clicks do nothing (v2.2.0), and Touchlink is unsupported. Test each press and build an HA automation. Do not promise HA-independent operation because a bind succeeded. [SNZB-01P](https://www.zigbee2mqtt.io/devices/SNZB-01P.html).

**`MS01` is ambiguous.** In Zigbee, `MS01`/`MSO1` are Gen1 model IDs of the **SNZB-03** PIR sensor, which exposes occupancy ([SNZB-03](https://www.zigbee2mqtt.io/devices/SNZB-03.html), [gateway report](https://github.com/AlexxIT/XiaomiGateway3/issues/738)). SONOFF also sells an **MS01 wired soil-moisture probe** with an RJ9 adapter for TH Origin/Elite ([MS01 probe](https://sonoff.tech/en-de/products/sonoff-ms01-smart-soil-moisture-sensor-with-rj9-adapter)). eWeLink context alone does not settle which one is present. A battery unit with occupancy clusters takes the Zigbee route. A cabled probe on a TH unit takes the host's sensor path. Do not configure irrigation from a model string.

**ZBM5 firmware 1.0.6.** It advertises an OTA server cluster and captures OTA discovery, which blocks updates for other devices in the network. The issue was open on 2026-09-22, and SONOFF said a firmware iteration would start around the end of October ([issue 33185](https://github.com/Koenkk/zigbee2mqtt/issues/33185), [ZBM5](https://www.zigbee2mqtt.io/devices/ZBM5-1C-80_86.html)). Direct binding needs 1.0.6 with detached mode enabled. Before any OTA campaign, check whether a ZBM5 on 1.0.6 is present.

## Reporting and practical tests

A 2025-07-07 report (Z2M 2.5.1, Ember 8.0.2) described a binding failure while changing SNZB-02P reporting. It was closed as not planned on 2025-09-15, which does not establish a fix ([issue 27919](https://github.com/Koenkk/zigbee2mqtt/issues/27919)). Check wake state, radio delivery and the actual write acknowledgment before concluding that a device cannot change its reporting.

Record the original interval and threshold. Change one sensor, observe its real reports, then judge the battery/latency tradeoff. For motion and presence, test entry, stillness, clear delay and retrigger. For buttons, test debouncing, and never bind an unsafe action to an ambiguous long press. For TH, probe or valve irrigation, keep a maximum run duration and an independent manual stop, so stale moisture data cannot water indefinitely. For relays and meters, follow the product's electrical instructions and use a qualified installer for mains work.
