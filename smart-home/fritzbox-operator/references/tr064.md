## Discover before calling

TR-064 is a service/action API, not a fixed URL list shared by every router. Obtain the device description, then follow `SCPDURL` for action argument order and types. Use advertised `controlURL` and full `serviceType` for SOAP. The bootstrap commonly uses `http://<router>:49000/tr64desc.xml`; discover HTTPS with `DeviceInfo:1` action `GetSecurityPort` rather than assuming a universal TLS port. See [FRITZ First Steps](https://fritz.support/resources/TR-064_First_Steps.pdf).

SSDP uses UDP multicast and normally remains within its local segment. Manual targeting can solve discovery failure when the TCP route is permitted; it does not remove router access restrictions. Failed multicast discovery does not prove SOAP is unreachable. Do not expose router management to WAN to make discovery work.

Save a description privately, then inspect offline:

```bash
curl --fail --show-error --max-time 10 \
  'http://192.168.178.1:49000/tr64desc.xml' \
  --output tr64desc.xml
python3 scripts/inspect_tr064.py tr64desc.xml
```

Replace the example address with the observed authorized router address. The bundled helper never downloads anything, executes actions, or follows XML URLs.

## Read-only examples

Use a maintained library pinned in the application's environment. `fritzconnection` exposes `call_action` for SOAP and `call_http` for AHA. Aliases such as `DeviceInfo1` are library names, not raw SOAP service URNs. See [project documentation](https://fritzconnection.readthedocs.io/en/latest/).

```python
from getpass import getpass
from fritzconnection import FritzConnection

router = input("Router address: ").strip()
username = input("FRITZ user: ").strip()
client = FritzConnection(
    address=router,
    user=username,
    password=getpass("FRITZ password: "),
)
# Confirm this alias/action in the actual service list first.
info = client.call_action("DeviceInfo1", "GetInfo")
print({key: info.get(key) for key in ("NewModelName", "NewSoftwareVersion")})
```

Configure transport/certificate behavior using the installed library's options. The example avoids secret-bearing command-line arguments and response dumps. A README's reconnect example is not a health check.

## Service families

Use the official service specification plus actual SCPD. Suffixes and aliases must be discovered.

| Family | Useful reads / scope | Mutation risk |
| --- | --- | --- |
| `DeviceInfo`, `UserInterface` | Model, firmware, events, update availability | Update can restart router |
| `DeviceConfig` | Configuration/session functions | Backup, restore, reboot, reset differ |
| `Hosts` | Known hosts, identity, IPs, activity, topology | WoL and edits affect endpoints |
| `WLANConfiguration` | Radio/SSID/association state | Radio/security changes evict clients |
| `WANIPConnection` / `WANPPPConnection` | WAN state and external address | Disconnect, credentials, port mapping |
| `WANCommonInterfaceConfig` | Traffic and physical WAN status | Bound measurement load |
| `LANHostConfigManagement`, `Layer3Forwarding` | Addressing, DHCP, routes | Can isolate HA |
| `X_AVM-DE_HostFilter` | Per-host internet access | Internet blocking is not LAN isolation |
| `X_AVM-DE_OnTel`, `X_VoIP`, `X_AVM-DE_TAM` | Phonebooks, calls, answering machine | Calls/forwarding have real consequences |
| `X_HomeAuto`, `X_AVM-DE_Dect` | Smart-home/DECT | Compare richer AHA/REST paths |
| Storage / Media / UPnP AV | NAS configuration, media, DVB-C | Do not infer file access/tuner entitlement |

Primary specifications: [Hosts](https://fritz.support/resources/TR-064_Hosts.pdf), [WLAN](https://fritz.support/resources/TR-064_WLAN_Configuration.pdf), [WAN IP](https://fritz.support/resources/TR-064_WAN_IP_Connection.pdf), [DeviceConfig](https://fritz.support/resources/TR-064_Device_Config.pdf). Cable and PPPoE installations expose different WAN paths; DSL samples do not establish Cable support.

## Authentication and errors

Distinguish HTTP errors from SOAP faults. Inspect status, fault code/string, action, and argument types without logging authorization. SOAP authentication and web SID login are separate; an AHA SID is not a password for an arbitrary SOAP call.

Some writes need physical confirmation. Respect the [authentication service](https://fritz.support/resources/TR-064_Authentication.pdf). Do not disable a security feature as a generic workaround.

| Observation | Investigate |
| --- | --- |
| No description | IP/port, route, guest isolation, app access |
| Description works; login fails | Username, permissions, firmware account behavior |
| Invalid action | Wrong service/version, absent action, SOAPAction |
| Invalid arguments | SCPD names/types/order, escaping, ranges |
| Read works; write denied | Rights, confirmation, provider/action restrictions |
| Timeout under load | Other pollers, long operations, router health |

## Implementation procedure

Cache descriptions with model, firmware, and retrieval time; refresh after firmware/topology changes. Build a read-only capability inventory before write automation. Bound timeouts, reduce concurrency, back off after failure, and prefer idempotent commands. Re-read the affected field after every write.

Treat returned download URLs as potentially short-lived credentials. Validate scheme and intended router origin before following them, and do not print tokens. Configuration exports and call lists can contain more sensitive information than the initiating query.

Compare code at the installed HA release and manifest dependency, not only a library's default branch. Keep changed clients in separate environments rather than editing HA's bundled packages.
